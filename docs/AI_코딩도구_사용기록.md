# AI 코딩 도구 사용 기록

미션 증빙 자료 "AI 코딩 도구 사용 과정(대화 로그 또는 스크린샷) 1세트"를 정리하는 문서입니다.
AI가 만든 코드를 그대로 쓰지 않고, **무엇이 문제였는지 이해하고 방향을 정해 수정한 과정**이 드러나도록 작성합니다.

> 이 문서의 "직접 겪은 오류"는 실제로 겪은 오류입니다. 제출 전에 본인의 말로 고쳐 쓰세요.
> 대화 로그를 첨부할 때 API 키, 개인정보가 보이지 않는지 꼭 확인하세요.

## 2. 주요 과정

### 2-1. AI 답변이 평범하다는 문제를 발견하고 개선 방향 정하기

- **발견한 문제:** AI 답변이 지나치게 단순하고 누구에게나 할 수 있는 말이어서, 타로를 볼 이유가 없다고 느꼈다.
- **내가 생각한 방법:** 답변에 제약·설정을 걸기, 더 좋은 AI 모델로 바꾸기.
- **AI와 논의해 정리한 원인 가설:**
  1. 질문과 관계없이 비슷한 답변이 나온다.
  2. 카드를 각각 설명할 뿐 카드 사이의 관계를 읽지 못한다.
  3. 질문의 구체적인 상황을 충분히 활용하지 못한다.
  4. 1차와 2차 리딩의 차이가 뚜렷하지 않다.
- **내가 내린 결정:** 프롬프트를 먼저 개선하고, AI 모델은 `claude-opus-4-8`로 바꾼다.
  (모델 사용량 차감 배수와 상관없이 품질을 우선하기로 판단)
- **지킨 원칙:** 잘 작동하던 카드 선택·결과 표시·2차 리딩 이동 기능은 건드리지 않고, 백엔드의 AI 요청과 프롬프트만 수정한다.

### 2-2. 프롬프트 개선 내용 (이번 수정)

| 개선 | 이유 |
|---|---|
| 카드마다 빛의 면 / 그림자 면 제공 | 카드를 한 가지 뜻으로만 읽지 않고 질문에 맞는 면을 고르게 하려고 |
| 고민 분야별 읽는 관점·단정 금지 항목 | 연애 질문과 진로 질문에 같은 조언이 나오지 않게 하려고 |
| 카드 사이의 관계(이어짐·충돌·반전)를 읽게 함 | 카드 해설서와 차별화하려고 |
| 어디에나 붙는 문장 금지, 행동은 기한·방법 명시 | 추상적인 위로 대신 쓸 수 있는 조언을 주려고 |
| 2차에는 1차 종합·조언만 전달, 새 관점 요구 | 2차가 1차의 반복이 되지 않게 하려고 |

### 2-3. 배포를 위해 구조 점검·수정한 내용

AI 도구로 프로젝트를 점검하면서 **미션 요구사항(Vercel Serverless Functions, `api/`)과 현재 구조의 차이**를 확인하고 고쳤다.

| 발견한 문제 | 원인 | 수정 |
|---|---|---|
| `api/*.py`가 Flask 앱을 import만 함 | 로컬용 Flask 구조를 그대로 가져다 쓰는 방식이라 배포 시 import 경로·번들링 위험이 있고, 미션의 "api/에 함수 구현"과도 거리가 있음 | 로직을 `api/_core.py`로 옮기고 각 엔드포인트를 `handler` 클래스로 작성. Flask는 로컬 개발 전용으로 유지 |
| 루트 `requirements.txt`에 Flask 포함 | 배포에 불필요한 패키지 | 배포용은 `openai`만, 로컬용은 `backend/requirements.txt`로 분리 |
| 심층 리딩 요청 한도가 16KB | 프롬프트 개선으로 1차 답변이 길어지면 2차 요청이 413으로 거절될 수 있음 | 64KB로 상향하고 항목별 길이(6,000자) 제한 추가 |
| 서버리스 실행 시간 설정 없음 | 성능이 높은 모델은 응답이 느릴 수 있음 | `vercel.json`에 `maxDuration: 60` 지정, 서버 AI 호출 타임아웃은 55초 |
| 연결 실패 시 "Flask 서버가 실행 중인지 확인해 주세요" 표시 | 개발용 문구가 배포 방문자에게 보임 | 개발 환경과 배포 환경의 문구를 분리 |

### 2-4. 직접 겪은 오류와 해결

> 미션은 "오류 원인을 파악하고 수정 방향을 말로 설명할 수 있어야 한다"를 요구합니다.
> 아래는 개발하면서 실제로 겪은 오류입니다. 제출 전에 본인이 이해한 대로 표현을 다듬어 주세요.

| 증상 | 원인 | AI에게 어떻게 물었나 | 어떻게 해결했나 |
|---|---|---|---|
| 사이트에서 "AI 서버에 연결할 수 없습니다. Flask 서버가 실행 중인지 확인해 주세요."가 뜨고, 사이트 주소가 5173에서 5174로 바뀜 | 이전에 켜 둔 Vite 서버가 5173을 계속 쓰고 있어 새 서버가 5174로 열렸다. Flask의 CORS는 5173만 허용하도록 되어 있어, 5174에서 보낸 요청이 브라우저에서 차단되었다 | 오류 화면과 터미널 화면을 캡처해 보여 주고, 주소가 바뀐 것과 오류 문구가 마음에 들지 않는다고 알렸다 | 남아 있던 Vite 프로세스를 종료하고, `vite.config.js`에 포트를 5173으로 고정(`strictPort`)했다. 배포용 문구와 개발용 문구도 분리했다 |
| 2차 심층 리딩이 502 "심층 리딩 답변 형식이 올바르지 않습니다"로 실패 | 카드 3장을 골랐는데 AI가 `hidden` 항목을 빈 문자열로 답했고, 서버의 형식 검사가 이를 오류로 처리했다. (처음에는 줄바꿈 때문에 JSON이 깨진 것이라고 추측했지만 서버 로그의 `hidden 항목이 비어 있습니다`로 원인이 달랐음을 확인했다) | 오류 화면과 서버 로그 캡처를 보여 주었다 | 선택한 카드 수(1·2·3장)에 따라 채워야 할 항목과 비워야 할 항목을 프롬프트에 명확히 적었다. JSON 파싱도 줄바꿈에 관대하게 바꿨다 |
| 연결 실패 시 개발용 문구("Flask 서버가 실행 중인지 확인해 주세요")가 배포 사이트에서도 보일 위험 | 개발 환경 기준으로 문구를 작성했다 | "Flask 서버가 실행 중인지 확인해 주세요" 문구가 마음에 들지 않는다고 알렸다 | `import.meta.env.DEV`로 개발/배포 문구를 나눴다 |
| 카드를 직접 고를 수 없는데 테스트 안내에는 특정 카드를 고르라고 되어 있었음 | 카드가 뒷면으로 놓여 랜덤으로 뽑히는 구조인데, AI가 이를 반영하지 않고 테스트 방법을 안내했다 | "카드는 랜덤으로 뽑히기 때문에 내가 임의로 정할 수 없다"고 알렸다 | 특정 카드에 의존하지 않는 테스트 방법으로 바꿨다 |
